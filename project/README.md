## Why the folders are split this way

Two systems are in play and they have different lifespans. Oracle Service Cloud is being retired. The Salesforce Government Cloud org is being built. Each has its own folder, so everything about one system is in one place.

Anything that only makes sense across both (the mapping framework, field mapping, the data migration plan, the cutover plan) lives in `migration/`. Discovery sessions get their own folder because they end; the system folders don't.

Paths in the inventory are relative to this folder. A row that starts with `../` points to another top-level folder.

## Conventions

- **Naming:** `<area>-<topic>-YYYY-MM-DD.md`. Transcripts use `YYYY-MM-DD-<topic>.md`; see their README.
- **One current version per artifact per folder.** A new version moves the one it replaces into `archive/YYYY-MM/` in the same change. Files amended in place (the register, the manifest) keep their names permanently.
- **Cite sources.** Any claim about the client's systems or intentions cites the transcript, document or query that supports it. A claim without a source is an assumption and gets labeled as one.
- **Counts in tables, assumptions labeled, verified separated from pending.** A deliverable that cannot say how many of something there are is not finished.
- **No em dashes.**
- **`extracts/` never gets committed and never leaves this machine.** See the hard rules in [CLAUDE.md](../CLAUDE.md).
